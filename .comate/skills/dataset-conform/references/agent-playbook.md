# 子代理分片修复手册

分片修复的成败几乎完全取决于给子代理的上下文质量。子代理看不到你的对话，也看不到整份数据——它只有你给它的那些字。

## 提交给每个子代理的内容

按这个模板写任务描述（照抄结构，替换尖括号内容）：

```
你在修复一份结构化数据集的一个分片，让它符合参考样例定义的格式与质量标准。

## 规格（必须先读）
- 规格说明：<绝对路径>/spec.md
- 机器校验规格：<绝对路径>/spec.json
- 参考样例（格式与质量的唯一基准）：<绝对路径>/sample_data.json
<若项目已有规则文档，一并列出路径>

## 你的分片
文件：<绝对路径>/shards/shard-003.json
结构：{"entries": [{"index": 数据集中的下标, "id": 条目 id, "issues": [已检出的问题], "entry": {条目本体}}]}

## 任务
逐条处理 entries：
1. 修掉 issues 列出的每一个问题。
2. 按 spec.md 的语义规则复核该条目，修掉机器校验发现不了的问题（<此处列出本数据集的语义规则要点，例如：归属是否真实、解释能否推出释义、译文是否忠实>）。
3. 不要改动与上述两项无关的任何内容。

## 硬性约束
- 条目守恒：进来 N 条，出去还是 N 条。不得新增、删除、合并、拆分条目。
- index 与 id 原样保留，一个字符都不能改。
- entry 必须是完整条目，不是差异片段。
- 无法确证的内容（例如指向外部文件的字段、你不确定的事实）保持原样，并写进 unresolved，不要编造。

## 输出
把修复后的分片写到：<绝对路径>/fixed/shard-003.json
格式与输入分片一致（保留 shard / container / idField / entries 结构，entries[].entry 替换为修复后的条目），
并为每条追加 "changes": ["改了什么，一句话"] 与 "unresolved": ["没能处理的问题及原因"]。
最终回复只给一段摘要：处理了几条、改了哪几类问题、有哪些 unresolved。不要在回复里贴数据。
```

## 为什么这样设计

- **传路径而不是传内容**：子代理自己读文件更省你的上下文，也避免转述失真。
- **`issues` 与语义规则分两步**：前者是清单式的机械修复，后者需要判断。合在一起讲，子代理往往只做前者。
- **`unresolved` 字段**：给子代理一个诚实的出口。没有这个出口，模型倾向于编一个看似合理的值填上——这是这类任务最难发现的损坏。
- **回复只要摘要**：分片数据已经落盘，让子代理复述一遍纯属浪费，还会挤掉你的上下文。

## 并发与调度

- 分片之间无依赖，一次尽量多派。单条数据较大时（每条几 KB），`--size 4~8`；条目小的（一行一个词条）可到 30~50。
- **幂等**：派活前检查 `fixed/` 里是否已有同名文件，有就跳过。中断后重跑只补缺失分片，这是 300 条规模能跑完的前提。
- 某个分片失败（子代理没写文件、写出的 JSON 解析失败）：单独重派该分片，不要重跑全部。`merge` 会把缺失分片报出来，缺失条目保留原值，不会静默丢数据。
- 同一分片连续失败两次，别再重试第三次——去读它的 issues 和 spec，通常是规格有歧义或该条目有结构性异常（比如整个字段类型都错了），需要你先处理。

## 子代理最常犯的四个错

1. **顺手改文风**：把没问题的句子重写一遍，制造大量无意义 diff，让人无法审阅。在提示词里明确"最小改动"并说明理由（用户要审 diff）。
2. **只输出改动字段**：合并后条目残缺。明确要求输出完整条目。
3. **靠编造满足数量约束**：例词补到 8 个、选项补到 4 个时，编出不属于该类别的内容。要在提示词里给出领域边界，并说明"凑数比缺项更糟"。
4. **改 id 或重排数组顺序**：破坏与外部资源（图片、音频、索引）的对应关系。明确禁止，并在 `merge` 阶段用守卫兜住。

## 验收

合并后必须做三件事，缺一件就等于没验证：

```bash
python <skill>/scripts/dataset_tool.py merge --data <原数据> --fixed-dir fixed --out merged.json --spec spec.json --report merge-report.md
python <skill>/scripts/dataset_tool.py audit --data merged.json --spec spec.json --out audit-after.json
python <skill>/scripts/dataset_tool.py diff --before <原数据> --after merged.json --out diff.md
```

看三件事：守卫告警是否为空、error 数是否真的下降、diff 里的变更字段分布是否与预期一致（出现了没打算改的字段路径，说明有子代理越界了）。
